# Numera Web — Design Specification

**Status:** Active — Phase 4 (interaction polish; command palette, FAB, snackbar shipped)
**Owner:** web platform — this document is the reference for the Android client
**Source of truth:** `web/src/styles/*.css` and `web/src/components/*.ts`

This document is the human-facing companion to the token CSS and the
actual component code. The rules below are mandatory; deviations require
a written rationale in the PR. §13 maps the web's current behavior to the
planned Android clients (phone / foldable / tablet).

---

## 1. Brand & Source Color

Numera picks **teal `#00696D`** as its primary source. It is calm,
low-saturation, and reads well in both light and dark — appropriate for
a tool meant to be open all day while crunching numbers.

The tone is generated by the Material color generator and lives in
`palette.css` as raw `--md-ref-palette-*` tokens. **No component may
import these directly.** They are the private input to `sys-color.css`.

Secondary and tertiary stay within the teal/blue family but with distinct
roles:

| Role | Intent | Used for |
|---|---|---|
| primary | Brand, key actions, focus | Save, primary CTAs, keyboard focus ring, link |
| secondary | Selection, supporting accent | Selected file row, FAB speed-dial action buttons |
| tertiary | Result highlights, positive accent | Calculation results, success states |

If a future feature needs a fourth tone (warning, info), it goes through
the same `palette → sys-color` pipeline. **Do not invent ad-hoc hex
values inside components.**

## 2. Token Architecture

```
palette.css     ─ raw tones, M3 generator output (private)
  ↓
sys-color.css   ─ semantic sys-color roles (light + dark)
  ↓
typescale.css   ─ typography roles (display/headline/title/body/label)
shape.css       ─ corner-radius roles (none … full + semantic aliases)
elevation.css   ─ shadow roles (level0–5 + semantic aliases)
state.css       ─ state-layer opacities + density/spacing roles + touch targets
motion.css      ─ easing curves + durations
  ↓
tokens.css      ─ single import point consumed by main.ts
```

A component imports `tokens.css` and only reads sys tokens. The split
into multiple files is purely for human review — the runtime sees one
cascade.

### 2.1 Why this split

- **Single layer of indirection.** Component code never sees a `#hex`
  literal; it sees `--md-sys-color-primary`. To re-skin Numera (white
  label, partner themes), only `palette.css` changes.
- **Color is special.** It is the only category that needs light/dark
  variants. Typography, shape, elevation, and motion are theme-agnostic.
- **Semantic aliases beat raw scales.** Components must read
  `--md-sys-shape-card` rather than `--md-sys-shape-corner-medium`.
  The alias names survive Material's next token overhaul.

### 2.2 Android alignment

The Android client must mirror this token layer 1:1 (same names, same
values) so a designer can reason about one system. On Android, the token
values are expressed in `dp`/`sp` (see §13 for the density/dimension
mapping); the `--md-sys-*` name is the contract, not the CSS unit.

## 3. Color Usage Rules

### 3.1 Surface ladder

Material 3 Expressive introduced an explicit five-rung surface ladder.
Numera uses it as-is:

| Token | Light tone | Dark tone | Use |
|---|---|---|---|
| `surface` | `#FAFDFC` | `#191C1C` | Default canvas (body) |
| `surface-container-lowest` | `#FFFFFF` | `#0D0F0F` | Inverse surfaces, full-bleed backgrounds |
| `surface-container-low` | `#EFF5F4` | `#191C1C` | Side panels, top bar |
| `surface-container` | `#E9EFEF` | `#1E2121` | Cards on the canvas |
| `surface-container-high` | `#E3EAE9` | `#282B2B` | Elevated surfaces (command palette panel) |
| `surface-container-highest` | `#E0E3E2` | `#323535` | Status bar, dev overlay, FAB action labels |

**Rule:** every nested surface moves up the ladder, never down. The
editor area is `surface`, the sidebar and top bar are
`surface-container-low`, a selected file row sits on
`secondary-container` (a tonal color, not a surface rung).

**Snackbar exception (code fact):** the snackbar uses
`inverse-surface` / `inverse-on-surface` / `inverse-primary` (action)
rather than a surface-container rung, so it stands out on any canvas.

### 3.2 State layers

State layers are not a separate color. They are opacity overlays:

```css
background-color: color-mix(
  in srgb,
  var(--md-sys-color-on-surface) calc(var(--md-sys-state-hover-state-layer-opacity) * 100%),
  transparent
);
```

This way, hovering *any* surface — list item, button, icon, FAB —
produces the correct tint without re-declaring per-component hover colors.

### 3.3 Accessibility floor

All text/background pairs must clear **WCAG AA**:

- Body text ≥ 4.5:1
- Large text (≥18.66px bold / 24px regular) ≥ 3:1
- UI components and graphics ≥ 3:1

`palette.css` tones were generated by Material's algorithm, which
guarantees these ratios for the default `on-*` pairings. Custom
combinations (e.g. tertiary text on surface) must be checked manually.

## 4. Typography

### 4.1 Roles

| Role | When to reach for it |
|---|---|
| `display-*` | Empty-state hero text, splash — currently unused |
| `headline-*` | Top-level screen titles — currently unused |
| `title-large` | Sidebar brand ("Numera") + top-bar filename + "Globals" title |
| `title-medium` | Section headers (currently unused) |
| `title-small` | Command palette item labels |
| `body-large` | Running prose (none yet — placeholders for docs/markdown preview) |
| `body-medium` | Default body text (reset baseline), snackbar message |
| `body-small` | Empty-state body copy, editor error tooltip |
| `label-large` | FAB action labels, snackbar action button |
| `label-medium` | Status bar mode indicator, dev overlay toggle |
| `label-small` | Dev overlay log entries, captions |
| mono aliases | Editor content, code references |

**Rule:** pick by intent, not pixel size. "It looks small" is not a
reason to choose `body-small` — choose `caption` intent (use label-small)
or `legal/footnote` intent (use body-small).

### 4.2 Fonts

| Family | Token | Used by |
|---|---|---|
| Roboto | `--md-sys-typescale-font-plain` | All UI text |
| JetBrains Mono | `--md-sys-typescale-font-mono` | Editor, dev overlay |

The brand font (`--md-sys-typescale-font-brand`) is currently Roboto.
To swap brand identity in the future, override this single token and
every headline/title that uses it updates. On Android, map
`font-plain` → Roboto (system default), `font-mono` → JetBrains Mono.

| Alias | Corner | Used by (actual) |
|---|---|---|
| `shape-text-field` | 4px (extra-small) | future text fields |
| `shape-button` / `shape-icon-button` | pill (full) | `@material/web` buttons |
| `shape-chip` | 8px (small) | dev overlay toggle |
| `shape-card` | 12px (medium) | dev overlay panel |
| `shape-dialog` | 28px (extra-large) | command palette panel |
| `shape-sheet` | 16px (large) | future bottom sheets |
| `shape-fab` | 16px (large) | **unused** — see note |
| `shape-snackbar` | 4px (extra-small) | snackbar |
| `shape-tooltip` | 4px (extra-small) | editor error tooltip |
| `shape-badge` | pill (full) | future badges |

**FAB note (code fact).** The FAB main button uses

role** to `shape.css` rather than inventing a one-off radius.

## 6. Elevation

Six physical levels (0–5) plus semantic aliases:

| Level | Role alias | Used by |
|---|---|---|
| 0 | — | Resting canvas surfaces |
| 1 | `card`, `nav-drawer` | Sidebar borders, soft cards |
| 2 | `menu`, `tooltip`, `bottom-sheet` | Dev overlay panel, FAB mini actions (`level2`) |
| 3 | `snackbar`, `dialog`, `fab-rest` | Command palette, snackbar, FAB rest (`level3`) |
| 4 | `fab-hover` | FAB hover |
| 5 | `fab-pressed` | FAB pressed |

Dark mode elevates by darkening the shadow opacity (50% / 30% blend
instead of 30% / 15%) so shadows remain perceivable on dark surfaces.

**Code fact:** the FAB references `--md-sys-elevation-level3` (rest),
`--md-sys-elevation-fab-hover` and `--md-sys-elevation-fab-pressed`
directly rather than the `fab-rest` alias; both resolve identically.

**Rule:** prefer the role alias (`--md-sys-elevation-card`) over a level
number when the intent is the goal (e.g. "this should look like a
card").

## 7. State Layers & Density

State-layer opacities follow Material 3 exactly:

| State | Opacity |
|---|---|
| hover | 8% |
| focus | 10% |
| pressed | 12% |
| dragged | 16% |

Density tokens follow a 4dp grid (with 8/12dp jumps for sectioning).
Components compose named roles (`--md-sys-spacing-block`) rather than
reaching for raw density values.

**Touch targets** — never smaller than 44px (iOS-style floor); default
to 48px (Material); use 56px for primary actions. Actual usage: the FAB
main button is 56px (`touch-target-large`), its mini actions are 44px
(`touch-target-min`).

**Layout primitives** (live in `state.css`):

| Token | Value | Use |
|---|---|---|
| `--md-sys-app-bar-height` | 64px | top bar |
| `--md-sys-bottom-bar-height` | 32px | status bar |
| `--md-sys-side-panel-width` | 280px | sidebar |
| `--md-sys-nav-rail-width` | 80px | navigation rail (reserved, unused) |

## 8. Motion

| Duration | Use |
|---|---|
| instant (0ms) | Opacity toggles synced to scroll |
| fast (100ms) | Hover state-layer fades |
| medium (200ms) | Property transitions on small elements, FAB speed-dial |
| emphasized (300ms) | Sidebar drawer, sheet open/close, FAB icon rotate |
| long (400ms) | Large-scale movements only |

`prefers-reduced-motion: reduce` collapses every duration to 0ms.

Easing: **emphasized** for everything user-perceivable (page
transitions, drawer slides). **Standard** for small property tweens
(opacity, color). **Linear is forbidden** outside progress indicators.
The FAB speed-dial uses `emphasized-decelerate` for its expand/collapse.

## 9. Layout Grid

Top-level shell uses a CSS Grid with three named rows and two named
columns. Tokens are kept in `state.css` so other layouts (future
navigation-rail mode, tablet split view) can reference the same
numbers.

| Region | Token | Width / Height |
|---|---|---|
| Top bar | `--md-sys-app-bar-height` | 64px |
| Status bar | `--md-sys-bottom-bar-height` | 32px |
| Sidebar | `--md-sys-side-panel-width` | 280px |
| Navigation rail | `--md-sys-nav-rail-width` | 80px (reserved) |

On expanded (desktop) screens the sidebar is a permanent, full-height
column spanning all three rows, while the top bar, editor, and status
bar live in the right column:

```css
grid-template-areas:
  'sidebar top-bar'
  'sidebar editor'
  'sidebar status-bar';
```

### 9.1 Breakpoints (code facts)

The shell switches layout at a **single 1024px** threshold. A secondary
**640px** threshold only tweaks minor chrome. There is no 640–1023 shell
variant today — below 1024px the sidebar is always a drawer.

| Threshold | Where | Effect |
|---|---|---|
| `max-width: 1023px` | app-shell | Sidebar becomes a fixed off-canvas drawer (`translateX(-100%)`), top/status bars span full width |
| `min-width: 1024px` | app-shell | Sidebar is a persistent 280px column; collapsible via `sidebar-collapsed` |
| `max-width: 1023px` | top-bar | Hamburger visible (drawer toggle) |
| `min-width: 1024px` | top-bar | Hamburger only shown when sidebar is collapsed |
| `max-width: 639px` | status-bar | Status hint truncates to 50% width |
| `max-width: 639px` | dev-overlay | Debug overlay repositions to a smaller inset |

Below 1024px the sidebar collapses into a fixed off-canvas drawer and
the top bar and status bar span the full width:

```css
grid-template-areas:
  'top-bar top-bar'
  'sidebar editor'
  'status-bar status-bar';
```

Overlay z-order (web reference for Android stacking):

| Element | z-index |
|---|---|
| Sidebar backdrop | 2 |
| Sidebar drawer (mobile) | 3 |
| FAB (+ scrim) | 4 |
| Dev overlay | 10 |
| Command palette backdrop/panel | 20 |
| Snackbar | 30 |

## 10. Component Conventions

### 10.1 Lit components

Every Lit component:

1. **Imports `tokens.css` indirectly** via the app shell — it never
   imports `tokens.css` itself (avoids cascade duplication).
2. Uses `static styles = css\`...\`` with `:host` defining the layout
   box (`display`, `width`, `height`, `background-color`, `color`).
3. Consumes only sys tokens. No hex values, no hard-coded font sizes.
4. Uses Lit's `.property` (not `attribute`) when the value is an object
   or array, to avoid JSON-in-attribute serialization.

### 10.2 Events

- **Out:** `CustomEvent` with `bubbles: true, composed: true` so
  events cross shadow boundaries.
- **In:** `@event-name=${this.handler}` in the template.
- Use semantic names: `file-select` not `click`.

### 10.3 Icons

Inline SVGs, 24×24 viewBox, `fill="currentColor"`. **No icon font.**
Icon set is component-local — when a component ships, it owns its
icon constants. (The globals button uses the Material "function"/f(x)
glyph, drawn as an inline SVG path.)

### 10.4 Accessibility

- Every interactive element has a visible label (`aria-label`) or
  visible text.
- Color is never the sole signal (selection uses both
  `secondary-container` background AND a pin icon / text emphasis).
- Focus rings follow `:focus-visible` and use
  `var(--md-sys-color-primary)`.
- The FAB exposes `aria-haspopup`, `aria-expanded`, `aria-controls`, and
  dismisses on Escape and on scrim tap.

| Component | File | Role |
|---|---|---|
| `numera-app` | `app.ts` | Root shell; wires keyboard bridge |
| `numera-app-shell` | `components/app-shell.ts` | Layout grid + owns the `WorkspaceStore`; wires all cross-component events |
| `numera-top-bar` | `components/top-bar.ts` | App bar: hamburger + title + actions (globals / settings / theme); renders "Globals" title + back button in globals mode |
| `numera-sidebar` | `components/sidebar.ts` | File list with selection + "new file" button |
| `numera-editor` | `components/editor-area.ts` | CodeMirror 6 editor; renders active file OR the globals document; per-line results/errors as inline decorations; WASM-backed live evaluation |
| `numera-fab` | `components/fab.ts` | Speed-dial FAB (new file / new draft / search) |
| `numera-command-palette` | `components/command-palette.ts` | Ctrl/Cmd+K modal for file switch + commands |
| `numera-snackbar` | `components/snackbar.ts` | Transient feedback (`show(message)`) |
| `numera-status-bar` | `components/status-bar.ts` | Mode indicator + command hint |
| `numera-dev-overlay` | `components/dev-overlay.ts` | Keyboard-bridge debug log (dev only) |

### 11.1 Interaction patterns (new)

**FAB speed-dial.** A single FAB (primary-container, 56px, bottom-end)
expands into three mini actions over a 0.32 scrim: **New file**
(`fab-new-file`), **New draft** (`fab-new-draft`), **Search**
(`fab-search`). Escape or scrim tap dismisses. The plus icon rotates 45°
when open.

**Globals editor.** The top-bar "global" button (`global-open`) switches
the single editor into "globals mode": it displays `globalsContent` as a
virtual file, the title reads "Globals", and a back button
(`globals-close`) returns to the active file. Selecting a sidebar file
also exits globals mode.

**Drafts.** "New draft" creates an ephemeral scratch file (`draft-N`)
that lives only in memory: it is never persisted, never appears in the
sidebar or command palette, and disappears on reload. It exists so a
user can do quick throwaway calculations without polluting the
workspace.

**Search migration.** Search moved from the top bar into the FAB. The
command palette remains reachable via Ctrl/Cmd+K.

## 12. Editor Pipeline

The editor is the centre of the closed loop. Every keystroke flows:

```
CodeMirror doc change
  → store.setActiveContent(text)
    → engine.setGlobals(globalsContent)
    → engine.evaluateDocument(text)
      → LineOutcome[]  (one entry per source line)
        → store.outcomes
          → re-render via outcomeDecorations() plugin
            → inline result / error widget per line
```

### 12.1 Eval semantics

- `engine.evaluateDocument(content)` first re-injects globals into
  numr-core, then evaluates each line top-to-bottom. Variable
  assignments compound (line 3 can read line 2).
- Empty lines and comments are reported with `isEmpty: true` — the
  decoration plugin skips them.
- Errors surface as `LineOutcome { isError: true, error: "..." }` and
  render with a wavy underline + an inline `⚠` widget.
- In **globals mode** (`editingTarget === 'globals'`), the globals
  document itself is evaluated line-by-line (no cross-file reference
  resolution), so the result gutter shows each global definition's
  value.

### 12.2 Globals namespace

Globals from `globals.numr` are exposed to expressions as
`global.<name>`. Two grammar forms are supported:

- **Variable**: `vat_rate = 0.2` → referenced as `global.vat_rate`.
  The namespace prefix is stripped before evaluation; numr-core sees
  the bare name.
- **Function**: `tax(price) = price * 0.13` → referenced as
  `global.tax(price)`. The function body is inlined at the call site
  via `function_call::expand_global_calls` before numr-core sees the
  expression (numr-core does not support user-defined functions).

Functions may call other functions; expansion is recursive up to a
bounded depth. Param substitution is positional; identifier boundaries
are respected (`price` is replaced, but `pricey` is not).

### 12.3 Cross-file references (`file("name")`)

Implemented in `web/src/lib/file-ref.ts` so semantics can iterate
without re-walking the WASM build cycle. The resolver:

- Builds an alias index per evaluation pass: path, path with `.numr`,
  basename, basename without `.numr`, display name.
- Walks each `file("name")` / `File('name')` occurrence and
  substitutes the **first exported variable's value** from the target
  file. An export is any non-blank, non-comment `name = value` line.
- Leaves unresolved references in place so the engine surfaces a
  clear diagnostic (unknown file or no exports).

The resolver runs **before** the document reaches the WASM engine.
The engine's own `ReferenceEvaluator` is kept as a fallback — the
two implementations should eventually be unified. The Rust
implementation is preferred long-term because it can do cross-file
type checking and handle multi-export references.

### 12.4 Persistence (IndexedDB)

`web/src/lib/persistence.ts` wraps IndexedDB in three object stores:

| Store | Key | Shape | Purpose |
|---|---|---|---|
| `files` | file id | `{ id, path, displayName, pinned, content, updatedAt }` | Per-file rows |
| `globals` | constant `current` | `{ content }` | The `globals.numr` body |
| `meta` | constant `current` | `{ schemaVersion, lastSavedAt }` | Hydration sentinel |

The store hydrates on construction via `WorkspaceStore.hydrate()`.
Mutation methods (`setActiveContent`, `setGlobals`, `createFile`)
schedule a debounced write (400ms). On first run (no snapshot), the
default fixtures are written out so subsequent reloads stay
consistent.

**Drafts are never persisted.** `createDraft` does not schedule a save,
and `persistNow` filters out `draft: true` files. They are in-memory
only.

### 12.5 Editor layout — 3-column table

The editor mirrors the NerdCalci / numr convention: a single table
with three columns on every row.

| Line number | Editor content | Result |
|---|---|---|
| 1 | `monthly_income = $6,500` | `→ $6,500` |
| 2 | `tax_rate       = 22%` | `→ 0.22` |
| 3 | `rent           = $1,800` | `→ $1,800` |
| 4 | `savings = ... - ...` | `→ 3124` |

Result rows are right-aligned in their own gutter, anchored to the
same `y` coordinate as the source line. They live in CodeMirror's
`gutter({ class: 'cm-result-gutter', markers })` extension so the
column scrolls in lock-step with the editor and shares the same
line-height as the source.

A no-op `forceRefresh` `StateEffect` is dispatched whenever the
outcome array changes, so the gutter re-reads `provider()` on each
evaluation pass. Without it, the gutter would only re-render on
viewport changes or doc edits.

Result cell visual states:

| State | Class | Look |
|---|---|---|
| Successful value | `.numera-result-value` | `tertiary` color, 500 weight, mono |
| Error | `.numera-result-error` | `error` color, dotted underline, "⚠ Err" + info icon |
| Empty / comment | `.numera-result-empty` | invisible (opacity 0) — keeps row height aligned |

Inline error underline on the source line is emitted by a separate
`errorLineDecoration()` ViewPlugin that only carries the wavy
underline; the result text itself stays in the gutter.

### 12.6 State management

`WorkspaceStore` is a thin pub-sub. Components subscribe via
`store.subscribe(listener)` and receive snapshots. There is no global
event bus, no observable library — the subscription list lives on the
store. Mutations are the only path that change state; each one triggers
a single broadcast and, for content changes, schedules a debounced
IndexedDB write.

Current state shape:

```ts
interface WorkspaceState {
  files: WorkspaceFile[];          // incl. in-memory drafts (draft: true)
  activeFileId: string | null;
  globalsContent: string;          // the globals.numr body
  editingTarget: 'file' | 'globals'; // what the editor is showing
  outcomes: LineOutcome[];
  mode: 'Normal' | 'Insert' | 'Standard';
  lastError: string | null;
  hydrating: boolean;
}
```

Mutation surface:

| Method | Effect |
|---|---|
| `selectFile(id)` | set active file + `editingTarget: 'file'` |
| `setActiveContent(text)` | edit active file (or globals, when in globals mode) |
| `setGlobals(text)` | edit globals + re-evaluate + save |
| `createFile(path, content?)` | add a persisted file |
| `createDraft(content?)` | add an ephemeral draft, no save |
| `openGlobals()` / `closeGlobals()` | toggle `editingTarget` |
| `setMode(mode)` | set the editor mode indicator |

The editor derives a single "display identity" — `'globals'` or the
active file id — and swaps the CodeMirror document only when that
identity changes, so snapshot broadcasts never reset the user's
in-progress text.

## 13. Adaptive Layout & Android Alignment

This section maps the web's current responsive behavior (the source of
truth) to the planned Android clients, which must support **phone,
foldable, and tablet**.

### 13.1 Form-factor → window-size class mapping

Use Material 3 canonical window-size classes rather than the web's
literal 1024px. The web's single 1024px switch corresponds roughly to
Material's **Expanded** class (≥ 840dp).

| Android class | Width | Web equivalent | Recommended chrome |
|---|---|---|---|
| Compact | < 600dp | phone | Modal navigation drawer + FAB + full-width top/status bars |
| Medium | 600–840dp | foldable (inner) / small tablet | Navigation rail (80dp) + FAB, or drawer; **no two-pane split** (matches web today) |
| Expanded | ≥ 840dp | tablet / unfolded foldable | Persistent 280dp sidebar (or nav rail) + editor + FAB |

The web currently has **no two-pane split view**; below 1024px the
sidebar is always a drawer, and above it is always a persistent column.
Android should reproduce this exact two-state behavior first, then
consider a true two-pane split as a later enhancement.

### 13.2 Dimension mapping

Web CSS pixels map to Android density-independent pixels for layout
dimensions:

| Web token | Web value | Android | Notes |
|---|---|---|---|
| app-bar height | 64px | 64dp | — |
| status bar height | 32px | n/a (Android system bars) | web's own status bar; Android uses system status/nav bars |
| sidebar width | 280px | 280dp (Expanded) | — |
| nav rail width | 80px | 80dp (Medium) | reserved, unused in web |
| FAB touch target | 56px | 56dp | primary |
| mini action target | 44px | 44dp | — |
| FAB surface radius | 28px | 28dp | `corner-extra-large` |

Type scale is `sp` on Android (1sp = 1dp at default font scale), but the
role *names* and relative sizes are the contract.

### 13.3 FAB + overlay positioning constraints

- The FAB is fixed **bottom-end**, offset above the status bar
  (`calc(bottom-bar-height + spacing-block-loose)`). On Android, offset
  above the **navigation bar / gesture inset** instead of a web status
  bar.
- Stacking (web reference, §9.1): drawer 3 / backdrop 2, FAB 4, dev
  overlay 10, command palette 20, snackbar 30.
- **Foldables:** never place the FAB or any overlay in the hinge gap.
  Snap the FAB to the nearest content edge and treat the hinge as a hard
  margin. In dual-screen postures, defer to a two-pane decision in a
  later phase (the web has no split view yet).
- The snackbar is bottom-center and must clear the FAB (web uses
  `z-index 30` above the FAB's 4).

### 13.4 State is form-factor agnostic (key invariant)

`files`, `drafts`, `globalsContent`, `editingTarget`, and `outcomes` are
all layout-independent. The same store can drive every form factor; only
the chrome changes (drawer vs rail vs persistent sidebar, FAB placement,
insets). Keep the state layer identical across web and Android so the
editor/eval engine is written once.

### 13.5 Globals & drafts are unaffected by form factor

- **Globals mode** is a per-surface concern (title swap + back button),
  independent of window width.
- **Drafts** are memory-only scratch buffers with no persistence and no
  list presence on any form factor.

Each phase keeps this document current — new tokens get a row here
*before* a component consumes them.

## 15. Forbidden Patterns

These show up in PR review as block-level comments:

1. **Hard-coded color literals** in components (`color: #fff;`,
   `background: red;`).
2. **Raw density values** (`padding: 13px;`) — compose tokens or
   propose a new density role.
3. **Raw typography values** (`font-size: 13px;`) — pick a role.
4. **Reference palette leakage** (`var(--md-ref-palette-primary40)`
   in a component).
5. **Linear easing** outside progress indicators.
6. **Touch targets < 44px** without a justification.
7. **Manual dark-mode overrides** inside a component (use
   `[data-theme="dark"]` blocks *only* in `sys-color.css` /
   `elevation.css`).

The same list applies to the Android client: no hard-coded colors or
raw `dp`/`sp` outside the token layer; express everything through the
`--md-sys-*` contract mapped to Android resources.

If a forbidden pattern is genuinely the right answer, document it in
this spec first, then implement.
